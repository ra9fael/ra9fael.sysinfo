# sysinfo：设置与搜索集成改进方案

[English](sdk-upgrade-plan.en.md)

## 改动原因

宿主卡片目前展示四十多项配置。指标布局需要填写分隔字符串，字体和颜色需要手写，玻璃材质又有大量数值参数，难以理解和调节。常用的穿透恢复等操作也容易淹没在长列表中。

插件已有配置回写能力，应复用现有更新路径。当前 UI 桥接只有原生监视窗，缺少独立设置窗口；鼠标穿透提示中提到的设置窗口恢复入口需要实际提供。

`main.cpp::queryResult()` 将基础结果对象按数组读取后重新包装，可能丢失 `items`。整理搜索入口时一并修正。

## 界面分工

| 入口 | 内容 |
|---|---|
| 搜索栏 | 监视窗状态、实时指标、设置入口；监视窗行提供显示、锁定、穿透和贴边隐藏动作；指标行支持复制 |
| 宿主卡片 | 显示开关、采样间隔、Tiny 模式、整体缩放、锁定位置、贴边隐藏、鼠标穿透 |
| 独立设置窗口 | 公共配置，以及布局、字体、波形、材质、位置、交互和录屏可见性等完整配置 |

独立窗口按功能分组：布局使用单元格选择和行列预览；字体提供选择器；波形颜色提供颜色选择和精确色值；材质、尺寸和百分比使用滑块与数值框。当前渲染器尚未实现的 `shadow` 不显示为可用控件，已有存储值保留。

## 实现方案

1. 更新 SDK，将 `updateHostSettings()` 调用改为 `updateSettings()`；保留基础查询的 `items`，追加刷新间隔。
2. 声明 `settingsWindow: true`，实现 `showSettings()`，排到 GUI 线程打开设置。搜索设置动作使用同一入口，重复打开聚焦已有窗口。
3. 公共简单配置由宿主持久化。独立窗口中对应控件通过 SDK 回写；收到宿主更新时只应用，不再次发送。
4. 从清单移出的高级项写入插件自己的配置文件，搜索快捷操作、设置窗口和监视窗操作共用现有设置存储与应用逻辑。窗口位置单独保留。
5. 移除高级项声明前确认旧值的可读方式。如果宿主在移除后不再提供该值，就在仍声明这些键时先读取并转存。仅处理受影响的键，不丢弃已有布局、颜色和材质配置。
6. 外观调整在监视窗实时预览。数值拖动在松开时提交，避免逐帧写盘；单项操作立即生效，不增加全窗口保存步骤。布局输入使用草稿，合法提交后应用。
7. 设置窗口跟随宿主语言、颜色和圆角；监视窗保留自身主题选项的含义。监视窗隐藏、锁定或穿透时，设置窗口仍可操作。

采样间隔沿用 100–5000 ms，缩放沿用 80–200%，其他范围取自现有校验。步长不得改变已有有效值。自动波形高度等特殊值使用明确的“自动”选项。

## 验收标准

- 搜索能显示监视窗及指标结果，并按间隔刷新。
- 搜索、宿主卡片和设置窗口修改公共项后保持一致，重启后保留。
- 高级项更换存储归属后保留用户原值。
- 布局、字体、颜色、材质调整有对应预览，提交值能够持久化。
- 穿透恢复入口始终可用；仅打开设置不会开启监视窗。
- 运行相关设置和协议测试；验证中英文、深浅主题与常用缩放。
